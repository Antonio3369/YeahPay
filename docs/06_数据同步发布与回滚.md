# 数据同步、发布与回滚

## 1. 目标流程

```text
OpenClaw 暗号
  → iMac 更新本地 DuckDB
  → 上传同一批 Excel/增量材料
  → 云端 ETL 写完整工作库
  → 生成 candidate/merchant.duckdb + candidate/ods_transactions_all-<摘要>.parquet
  → 本地与云端逻辑指纹比对
  → 回写一致性、两源最新日期、候选文件身份
  → 管理员打开“数据更新确认”
  → 管理员确认
  → active 双文件备份 + candidate 双文件安全切换为 active
  → 写入 biz.db.settings.data_refresh_date
  → 所有 API 按新截止日读取
```

前端“确认更新”不是执行 Excel 导入，而是发布已经准备好并通过校验的候选运行包。

## 2. 运行包结构

`merchant.duckdb` 保存 API 需要的维表和汇总表；`ods_transactions_all` 在其中是读取同目录内容寻址 Parquet 的视图。Parquet 保存全部交易行、完整时间范围和 API 实际使用的 16 个交易字段。后端的候选身份摘要同时包含两个文件的文件名、大小和纳秒修改时间；任一文件变化都会使旧校验自动失效。

## 3. 两个数据源与可发布日期

- 交易明细最新日期：成功交易 `ods_transactions_all.created_at` 的最大日期。
- 近30天汇总最新日期：`transaction_amounts.trans_date` 的最大日期。
- 可发布日期：两个日期的较早者。

候选库一致、可发布日期晚于当前已确认日期、当前账号为 admin，三者同时满足时按钮才应可用。

## 4. ETL 语义

### 交易明细

- 增量写入。
- 使用订单号等稳定业务键幂等去重。
- 重跑同一文件不应增加重复交易。
- 导入失败整批回滚，不留下半批数据。

### 商户/代理商/销售主数据

- 使用完整快照替换或带注销状态的快照合并。
- 不可只 UPSERT 而永不删除，否则 Excel 已删除的商户会永久残留。
- 发布前输出新增、删除、改名、改代理商、改销售归属的差异报告。
- 测试商户按统一规则排除，并单独计数。

## 5. 一致性校验

`source/data-sync/verify_duckdb_sync.py`比较核心表的：

- 行数；
- 与行顺序无关的逻辑摘要；
- 日期覆盖。

不能比较 DuckDB 文件二进制 SHA 来判断逻辑一致，因为相同数据的存储布局可能不同。二进制 SHA 只用于确认交接包文件未损坏。

每次新候选库都必须重新生成一致性结果，并把结果绑定到候选文件的身份摘要/批次号。禁止复用上一候选库的“通过”状态。

完整 ETL 库和轻量运行包通过 `verify_duckdb_sync.py` 比较时，交易明细按 API 使用的 16 列计算逻辑摘要；其余核心表比较全行摘要。这样可以验证查询语义一致，而不要求二进制布局相同。

## 6. 发布安全门

发布前至少检查：

- 候选库可以只读打开且核心表存在；
- 两源日期存在，发布日期不倒退；
- 本地/云端逻辑指纹一致；
- 有效商户减少比例不超过配置安全阈值；
- 测试商户排除数、孤儿汇总 ID 数有报告；
- 当前 active 可创建备份；
- candidate 与 active 位于同一文件系统，且 DuckDB 引用的 Parquet 存在于同目录；
- 候选双文件联合身份与本批次校验记录完全一致。

## 7. 回滚

发布顺序：

1. 停止新的发布操作，不必停止只读查询。
2. 将 active 的 DuckDB 与 Parquet 一起放入带时间戳备份目录。
3. 先把内容寻址 Parquet 放到 active 目录，再原子替换 DuckDB 入口文件。
4. 从正式路径重新打开双文件运行包并只读健康检查。
5. 写入 `data_refresh_date` 和批次信息。

若第 4 或第 5 步失败，恢复上一完整运行包，并保留原 `data_refresh_date`。不能只回滚 DuckDB、只回滚 Parquet 或保留新的发布日期。

## 8. 同步脚本说明

交接包保留了 `source/data-sync/sync_hk_db.sh` 编排模板，不能免配置用于生产。接管方必须配置 iMac 路径、云端主机、完整 ETL 工作库、candidate 运行包和 `biz.db` 路径；云端 ETL 只能更新完整工作库，不能直接写 active。

`cloud_etl.py` 先更新完整工作库，`build_runtime_bundle.py` 再生成查询运行包，`verify_duckdb_sync.py` 比对逻辑数据，`mark_sync_verified.py` 最后绑定联合候选指纹。上线前以后端 `confirm-data-refresh` 实际校验为准。

## 9. 小程序状态接口

- `GET /api/v1/v2/admin/data-refresh-status`
- `POST /api/v1/v2/admin/confirm-data-refresh`

精确请求/响应字段见 OpenAPI。前端显示交易明细日期、近30天汇总日期、逻辑一致性、可发布日期和当前确认日期。
