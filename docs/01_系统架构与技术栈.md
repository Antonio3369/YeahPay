# 系统架构与技术栈

## 1. 系统边界

```text
微信小程序
   │ HTTPS + JWT
   ▼
Nginx / Cloudflare（b-api.seeya.icu）
   │
   ▼
FastAPI（/api/v1）
   ├── DuckDB + Parquet：商户、交易、汇总，只读查询
   └── SQLite：账号、范围、预警、推送、跟进、复盘、发布日期

iMac/OpenClaw
   └── Excel → 完整 ETL 库 → 轻量候选运行包 → 一致性验证
                                          │
                                          └── 管理员确认 → 正式运行包
```

小程序不直接访问数据库，也不负责执行 ETL。后端是权限、口径和发布门控的唯一入口。

## 2. 技术栈

| 层级 | 技术 | 说明 |
|---|---|---|
| 小程序 | 微信原生 WXML/WXSS/JavaScript | 无 npm 构建步骤，ECharts 通过 `ec-canvas` 组件运行 |
| HTTP 客户端 | `wx.request` 封装 | JWT 注入、401 处理、超时与错误提示集中在 `utils/api.js` |
| 后端 | Python 3.11、FastAPI、Uvicorn、Pydantic v2 | 版本锁定见 `source/backend/requirements-lock.txt` |
| 分析库 | DuckDB 1.4.5 + ZSTD Parquet | 运行包约 82MiB；交易行与完整时间范围保留，未使用列不进入运行包 |
| 业务库 | SQLite 3，WAL 模式 | 小体量、可写、单实例写入；当前文件为 `biz.db` |
| 鉴权 | JWT HS256、bcrypt | 账号密码只存 bcrypt Hash，不应导出明文 |
| 图表 | ECharts | 柱状、折线、环形图；切换页面后需要按页面生命周期重新 resize/init |
| 部署 | Ubuntu、Nginx、systemd/Uvicorn | 当前服务器公网 IP：`43.134.104.94`，登录用户：`ubuntu` |

## 3. 源码结构

### 小程序

- `app.js/app.json/app.wxss`：全局生命周期、页面注册、全局样式。
- `pages/`：工作台、商户、预警、飞虎队、我的及详情/管理页面。
- `utils/api.js`：API 请求入口。
- `utils/auth.js`：Token、角色和当前数据视角。
- `utils/config.js`：API 域名与超时。
- `utils/format.js`：HKD、百分比、万/亿展示。
- `utils/chart-theme.js`：图表颜色和文字样式。
- `ec-canvas/`：ECharts 小程序适配层。

### 后端

- `main.py`：FastAPI 入口和路由注册。
- `api/`：认证、账号、商户、预警、推送、复盘等 v1 路由。
- `api/v2/`：工作台、业绩、详情、更新发布等扩展路由。
- `core/`：配置、数据库连接、权限范围、数据日期与统一 SQL 口径。
- `models/`：Pydantic 请求/响应模型。
- `service/`：预警、人工任务、数据池等跨路由业务服务。
- `tests/`：口径、发布门控和逻辑回归测试。

## 4. 两个数据库为什么不能合并或少交一个

DuckDB 可以被新的完整候选库替换；SQLite 不能跟着替换。否则账号、账号范围、预警处理状态、商户推送、跟进记录、复盘报告和已确认发布日期会全部丢失。

生产环境建议：

```text
/opt/yeahpay/app/                    后端代码
/opt/yeahpay/app/data/biz.db         持久化业务库
/opt/yeahpay/data/active/            当前正式 DuckDB + 同目录 Parquet
/opt/yeahpay/data/candidate/         待发布 DuckDB + 同目录 Parquet
/opt/yeahpay/data/backup/            每次发布前的双文件版本目录
/opt/yeahpay/etl/                    ETL 与一致性脚本
```
