# 运行维护与故障排查

## 1. 日常检查

```bash
systemctl status yeahpay-backend
journalctl -u yeahpay-backend -n 200 --no-pager
curl -fsS https://b-api.seeya.icu/health
df -h
free -h
```

数据库检查：

```bash
python tools/verify_metrics.py --duckdb data/merchant.duckdb --sqlite data/biz.db
sqlite3 data/biz.db 'PRAGMA integrity_check;'
```

运行包约 82MiB，但仍应按只读方式连接；大型聚合应在 SQL 内完成并分页返回。

## 2. 性能原则

- 列表必须服务端分页，默认 20 条，返回全量 `total`。
- 全量搜索在 SQL 条件中执行，不在小程序对当前页过滤。
- 小程序不加载整表，不把大数组放进 `setData`。
- DuckDB 复用后端连接策略，避免每个图表反复扫描不同口径的全表。
- 大型接口应记录耗时，并优先建立按日期、商户、代理商、销售预聚合表。
- SQLite 使用 WAL 和单写锁；生产只运行一个会写 SQLite 的应用实例，或迁移到服务型数据库。

## 3. 常见故障

### 小程序白屏

检查开发者工具 Console 第一条异常，尤其是页面未注册、JS 语法错误、登录启动页错误。核对 `app.json.pages` 与实际目录；不要把网络失败误判成页面不存在。

### 登录显示网络请求失败

检查：API 域名、TLS 证书链、微信 request 合法域名、Nginx、后端健康、手机网络 DNS。先用手机浏览器访问 `/health` 只能证明网络通，不代表 JWT 接口正确。

### 图表偶尔空白

ECharts canvas 在 tab 切换、overlay `wx:if` 卸载、页面 hide/show 后可能失去尺寸。应在 `onReady/onShow` 且容器已有尺寸时 init/resize；隐藏页面时使旧异步请求失效。不要在每次 `setData` 中无条件销毁重建全部图表。

### 同页数字互相矛盾

先比较 API 原始值，不比较“万/亿”格式化文本。确认范围、`as_of_date`、成功状态、正金额、有效商户过滤完全一致，再运行 `tools/verify_metrics.py`。

### 预警数量等于 20/40

这是把已加载页数当全量。页面必须显示响应 `total`，后端 count 查询使用和 items 相同的状态、标签 AND、关键词和权限范围。

### 数据更新按钮不可点击

检查管理员身份、candidate 是否存在、两源日期、`needs_refresh`、一致性是否绑定当前候选、发布日期是否晚于已确认日。不要在前端强行解除禁用绕过安全门。

### `ods_transactions_all-*.parquet` 找不到

说明只复制了 `merchant.duckdb`、文件被改名，或两文件不在同一目录。恢复与 DuckDB 同一版本的内容寻址 Parquet；不要把视图改成机器绝对路径。执行 `python tools/verify_metrics.py --duckdb data/merchant.duckdb --sqlite data/biz.db` 验证。

### `database is locked`

确认 SQLite 在本地磁盘、WAL 可用、没有多个独立写服务或人工 sqlite3 长事务。先备份，再排查持锁进程；不要删除 `biz.db-wal` 来“修复”。

## 4. 备份

- 分析运行包：每次发布前在同一版本目录保留 DuckDB 与 Parquet；按容量制定保留周期。
- SQLite：使用 SQLite backup API 或暂停写入后复制主库、WAL、SHM；定期做恢复演练。
- 源码：公司 Git 仓库保护主分支和发布标签。
- 密钥：公司密码管理器保存，不进入源码压缩包。

## 5. 监控建议

- `/health` 可用率与延迟。
- 5xx、401、查询超时数量。
- active/candidate 双文件总大小、文件年龄、联合指纹与最新业务日期。
- 磁盘剩余空间和内存交换。
- 每批 ETL 行数、重复数、删除主数据数、孤儿 ID、测试商户排除数。
- 数据发布日期滞后天数。
