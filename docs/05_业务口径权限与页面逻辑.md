# 业务口径、权限与页面逻辑

## 1. 统一业务截止日

所有滚动日期以 `biz.db.settings.data_refresh_date` 为 `as_of_date`：

- 本月：`as_of_date` 所在月 1 日至 `as_of_date`。
- 上月同期：上月 1 日至与 `as_of_date` 对应的日；若上月没有该日，取上月最后一天。
- 近一周：截止日向前 6 天。
- 前一周：近一周之前连续 7 天。
- 近一月/前一月同理按连续窗口计算。

禁止用 `CURRENT_DATE`、服务器系统日或手机当前日直接计算业务指标。发布日期未设置时，门控逻辑应失败关闭，而不是暴露候选日期的数据。

## 2. 有效商户

统计与列表的商户全集必须使用后端统一过滤条件：

- 已绑定硬件/满足当前有效绑定规则；
- 未注销、未明确取消；
- 商户名称不属于测试商户；
- 商户 ID 有效。

测试商户应排除。近30天汇总里存在但主表不存在的 ID 不能自动变成正式商户；ETL 需要给出孤儿记录报告。

## 3. 交易金额和状态

- 成功交易金额：`trans_status = '交易成功'` 且 `amount > 0`。
- 交易额统计按 HKD 原值聚合，不在 SQL 中先除以万或亿。
- 卡包与状态图必须和 KPI 使用相同数据截止日、范围和有效商户集合。
- 交易失败比例：近一个月失败交易笔数 / 同期全部有明确交易状态的交易笔数，前端保留两位小数。
- 商户户均交易额：本月成功交易额 / 本月活跃商户数；分母不是总商户数。
- 月活跃商户：本月截至业务截止日有成功正金额交易的有效商户。

## 4. 工作台一致性

同一视角下必须满足：

- KPI 本月交易额 = 月度趋势最后一个月同截止日金额。
- KPI 总商户/活跃商户与相同范围商户列表、明细口径一致。
- 本月户均 = 本月交易额 / 本月活跃商户。
- 所有工作台接口使用同一 JWT 数据范围和显式管理员视角参数。

前端的 `万/亿`和小数位仅是显示，不允许拿格式化字符串继续计算。

## 5. 角色与数据范围

| 能力 | admin | supervisor（代理商层级） | sales |
|---|---:|---:|---:|
| 工作台 | ✓ 全部并可切视角 | ✓ 绑定范围 | ✓ 绑定销售范围 |
| 商户列表与详情 | ✓ | ✓ 范围内 | ✓ 范围内 |
| 预警/推送/跟进 | ✓ | ✓ 范围内及被推送 | ✓ 范围内及被推送 |
| 飞虎队/团队排名 | ✓ | ✓ | 不展示业务数据 |
| 销售业绩管理 | ✓ | ✓ | 不展示业务数据 |
| 账号与阈值管理 | ✓ | 不可 | 不可 |
| 数据更新确认 | ✓ | 不可 | 不可 |

`user_scope_bindings` 支持一个代理商账号绑定一个代理商、一个或多个销售，后端按集合并集计算可见商户。前端隐藏页面不能替代后端鉴权。

被推送商户即使不属于接收销售原数据范围，接收方也应获得该商户完成任务所需的临时详情权限；任务解决后是否继续保留访问，需按当前服务逻辑和公司政策评审。

## 6. 预警规则

当前预警类型：

| 标签 | 判断口径 | 默认值 |
|---|---|---:|
| 未激活 | 激活后指定天数内累计交易额低于 HK$100 | 14 天 |
| 已沉默 | 最后成功交易距业务截止日超过阈值 | 180 天 |
| 交易周环比下降 | 近一周较前一周下降超过阈值 | 50% |
| 交易月环比下降 | 近一月较前一月下降超过阈值 | 50% |
| 交易失败 | 近一月失败比例超过阈值 | 50% |
| 交易异动 | 近一周较前一周上升超过阈值 | 300% |

一个商户可同时命中多个标签。多标签筛选采用 AND，即必须同时满足所有已选标签；搜索是当前标签结果集上的全量服务端搜索，不是只搜索当前已加载 20 条。

列表顶部 `total` 必须来自服务端筛选后的全量计数，不可使用当前页数组长度。待跟进、跟进中、已解决都应继续遵守标签与搜索条件。

## 7. 推送、跟进和复盘

1. 任意有详情权限的账号可在商户详情选择接收账号并推送。
2. 接收方在预警页收到消息提示并开始跟进。
3. 未解决前，推送方和接收方均能在跟进中查看任务。
4. 解决时记录线上/线下触达、是否解决及备注。
5. 解决后进入已解决和复盘列表。
6. 复盘页基于解决日后的成功交易变化做效果对比，数据不足时明确显示“观察期不足”，不得填造数据。
7. Excel 导出由后端按权限和筛选条件生成，不能由前端导出当前页冒充全量。

## 8. 新增、删除与改名适配

- 商户主数据是快照语义：新快照删除的商户应从新正式 DuckDB 的有效主表消失或明确标记注销。
- 交易明细是增量/去重语义：以稳定订单主键去重，不能重复累加。
- 新代理商或销售发布后，范围选择接口应自动从新主数据读取。
- 已保存的管理员视角在新库不存在时，小程序回退到“全部机构”。
- `biz.db` 里的历史任务不应因主数据删除而物理丢失；页面应保留历史名称并标明主数据已失效。
